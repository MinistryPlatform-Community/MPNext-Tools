### Open, no fix exists: `braces` (accepted, lint-time only)

[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm),
published 2026-09-18: stack-exhaustion DoS from deeply nested brace patterns.
OSV range is `introduced 0, last_affected 3.0.3`. That is a real range, not the
malformed `introduced: 0` with no events, and 3.0.3 is the **latest published
`braces`** (last publish 2024-09). So no patched version exists.

`npm audit` counts it **5 times**, once per node of the chain:

```
eslint-config-next@16.4.0
└─ @next/eslint-plugin-next@16.4.0   (pins fast-glob 3.3.1 exactly)
   └─ fast-glob@3.3.1
      └─ micromatch@4.0.8
         └─ braces@3.0.3
```

The fix `npm audit` offers is `eslint-config-next@14.2.35`. That is a downgrade
across two majors, so it is not a fix. An `overrides` entry cannot help either,
because there is no fixed `braces` to override to.

**Exposure is lint-time only.** The only path is the ESLint plugin, which globs
patterns from the repo's own config. It is not in the app bundle and never sees
request data. Accepted. It clears when `braces` publishes a fix (or
`micromatch`/`fast-glob` drops it) **and** `@next/eslint-plugin-next` moves off
its exact `fast-glob@3.3.1` pin, if the fix doesn't land in 3.3.1's own range:

```bash
npm view braces version && npm view @next/eslint-plugin-next dependencies
```
